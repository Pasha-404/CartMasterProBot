# CartMasterProBot: актуальные заметки для Terra

## Текущее состояние

- Бот принимает `POST /webhook` и до обработки update проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.
- Повторные Telegram update не обрабатываются дважды: в памяти хранится до 10 000 `update_id` в течение 15 минут.
- Нажатие inline-кнопки возвращает `answerCallbackQuery` и редактирует активное сообщение со списком.
- Название товара ограничено 30 символами, в списке может быть не более 20 товаров.
- После покупки последнего товара бот сохраняет завершённый список в чате и создаёт отдельный новый пустой список.
- Значок товара выбирается только для отображения; исходное название не меняется.
- Секреты доступны приложению только через `BOT_TOKEN` и `WEBHOOK_SECRET` на VPS.
- Push в `master` собирает проект, деплоит его на VPS и проверяет состояние `cartmasterprobot.service`.

Не менять webhook на long polling, не добавлять секреты в код или логи и не создавать второй Spring bean либо второй controller для webhook.

## Принятые продуктовые решения

- Списки хранятся только в памяти и сбрасываются после рестарта приложения. Постоянное хранилище сейчас не требуется.
- В групповом чате участники используют один общий список, привязанный к `chatId`. Раздельные списки по `chatId + userId` сейчас не нужны.

## Отложенная техническая задача: миграция TelegramBots

Проект использует `telegrambots-spring-boot-starter 6.9.7.1` и устаревший базовый класс `TelegramWebhookBot`. Бот работает; миграция не добавит пользовательских функций и не нужна срочно.

Планировать её отдельной небольшой задачей перед крупным обновлением Spring Boot или TelegramBots, либо если текущая версия перестанет получать необходимые исправления. Цель миграции — перейти с устаревшего API на поддерживаемый, сохранив текущий webhook-режим и поведение бота.

Требования к будущей миграции:

- сохранить путь `/webhook` и проверку secret header до обработки update;
- не создать второй Spring bean или второй controller;
- сохранить `answerCallbackQuery`, редактирование списка и защиту от повторных update;
- не логировать token, webhook secret, тексты сообщений, chat ID и user ID;
- добавить или скорректировать тесты и выполнить `mvn clean package`;
- не смешивать миграцию с изменением бизнес-логики или хранилища данных.
